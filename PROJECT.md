# PROJECT.md

Standalone PHP qBittorrent Web API v2 client library (`Blackout\Qbittorrent\*`).
UTF-8 safe handling, DTO layer over the raw API. The download-automation
scripts, RSS/HNR tooling, and tracker scrapers that used to live alongside
this code now live in the separate `UnkyBadTouch/qbittorrent-tools` repo,
which requires this package via a composer VCS dependency (split 2026-07-20).

## Layout

- `src/Qbittorrent/Client.php` — qBittorrent Web API v2 client (Guzzle). `src/Qbittorrent/Helper.php` (`Blackout\Qbittorrent\Helper`) holds qBittorrent-only utility functions split out from the generic `Blackout\Helper` (`normalizeUtf8`/`normalizeArrayUtf8`, `extractKey`, `extractKeys`, `isBrowser`). `Blackout\Helper` (`src/Helper.php`) and `Blackout\FileLock` (`src/FileLock.php`) stay in this repo because `Client`/DTOs depend on them directly — the tools repo picks them up transitively via the composer dependency on this package.
- DTO classes live in `src/Qbittorrent/DTO/` (namespace `Blackout\Qbittorrent\DTO`).

## qBittorrent API gotchas

- Never pass `savepath` to `/torrents/add`.
- `/torrents/add` normally returns plain text `"Ok."`, but some paths (proxy/tracker-dependent) return a JSON success payload like `{"added_torrent_ids":[...],"success_count":1,"failure_count":0}` instead. `Client::addTorrentUrls()`/`addTorrentFile()` check both shapes via `isAddTorrentSuccess()`; on real failure, `describeAddTorrentFailure()` extracts `error`/`message`/`reason` from JSON bodies rather than dumping raw text.
- **Master source for endpoints/fields**: the local qBittorrent C++ source clone at `~/.cache/qbittorrent-reference/qBittorrent-src`, not the wiki. `git checkout release-X.Y.Z` to the tag matching the live instance's version (`getVersion()`), then read `src/webui/api/*.cpp` (`grep -oP '^void \K\w+Controller::\w+Action' *.cpp` lists every real route) and `src/webui/api/serialize/*.cpp`/`src/base/rss/*.cpp` for field shapes. The wiki (`WebUI-API-(qBittorrent-5.0)`) is stale/incomplete/wrong-shape in places (worst for RSS and search — 4.1 and "current" 5.0 pages are identical copies; search field names are paraphrased, not real) and only covers a 5.0 baseline, missing every 5.1+ endpoint. There's also a live qBittorrent-nox instance on this box (connection details live in a gitignored `*.local.php` config) — probe it through `Client`, `json_encode` the result, and diff raw vs. hydrated keys to catch silently-dropped fields; use it to *verify* what the source says, not instead of reading the source.
- `Client` endpoint coverage is currently complete against the version-matched C++ source (last audited 2026-07-12) — if a future qBittorrent upgrade adds endpoints, re-diff `Client.php` against the new release tag's `src/webui/api/*.cpp` rather than trusting the wiki.
- Undocumented `rss/cloneRule` (`sourceName`/`cloneName`, `RSSController::cloneRuleAction()`) — not on the wiki, and not in any tagged release either (only on `master`, ahead of 5.2.2). `Client::cloneRssRule()`/`Rule::clone()` exist and match the eventual API shape, but 404 ("Endpoint does not exist") until qBittorrent actually ships a release containing it — don't trust them live yet.

## DTO layer (src/Qbittorrent/DTO)

- `Base.php` hydrates public typed properties from a raw API array via reflection (`hydrate`/`castProperty`) — casts scalars, backed enums, and nested `Base` subclasses; unmapped/no-key fields are silently skipped (no error), so a property using the wrong name for the actual API field just never populates. The injected `Client` is `protected ?Client $qbittorrent` (constructor-promoted) — deliberately not named `$client`, since a subclass declaring its own public `client` property (e.g. `Torrent/Peer`'s API `client` field) would collide with the parent's typed property and fatal at first instantiation.
- Nested collections (`Torrent::$files/$trackers/$peers/$pieces`) are lazy: declared as hooked `get` properties, loaded on first access via `#[Relation(method, class)]` calling back into `Client`. `#[Relation(..., Foo::class)]` needs `Foo` imported with `use` — an unqualified `Foo::class` with no import silently resolves to the *current* namespace's `Foo` and only fatals the first time the relation is accessed.
- PHP 8.4 property hooks: a property with only a `set` hook keeps normal storage/`get` behavior, fires via both direct writes and `ReflectionProperty::setValue()` (so it fires during `Base::hydrate()` too), and can write into an uninitialized sibling typed-array property without error (`$this->other['k'] = $v` auto-vivifies). Used by `Rss/Rule` to mirror deprecated fields into `torrentParams` (see below).
- Convention: every new single-entity `Client` method gets a matching DTO wrapper in the same change. It calls the `Client` method with the DTO's own identifier, then either updates the matching local field, flips it for a toggle, unsets the cached `_relations` entry so a lazy relation refetches, or unwraps a hash-keyed map return for a getter. Action-only calls with no DTO-tracked field (`recheck`, priority reorder) just proxy. Exception: `Rss/Rule` has no per-field endpoint at all (only whole-object `setRule`) — it gets `save()` instead (serializes via `jsonSerialize()` minus the synthesized `name`, POSTs the lot) rather than per-field wrappers.
- Convention: any param that's really a list of items (`$hashes`, `$tags`, `$categories`, `$urls`, `$plugins`, `$sources`, `$names`) is typed `string|array` and cast with `(array)` before `implode()`, so a single item can be passed bare. Associative-array params (`$query`, `$prefs`, `$ruleDef`, `$options`) are NOT part of this convention.
- Booleans go over the wire as the strings `'true'`/`'false'`, not PHP bools.
- Audited/filled-out DTOs: `Torrent`, `Torrent/File`, `Torrent/Tracker`, `Torrent/Peer`, `Torrent/Piece`, `Torrent/WebSeed`, `Torrent/Properties`, `Category`, `Preferences`, `Rss/Rule`, `Rss/Feed`, `BuildInfo`, `Transfer`, `Log/Message`, `Log/Peer`, `Search/Result`, `Search/Status`, `Search/Plugin`. Still a raw array: `Client::syncMainData()` (composite: `server_state`, `categories`, `torrents`, `tags`, `trackers` — no natural single-entity DTO home, same for `torrentcreator`/`clientdata`/`app` system-info groups).
- `getTorrentFiles()`/`getTorrentTrackers()`/`getTorrentWebSeeds()`/`getTorrentPeers()`/`getTorrentPiecesStates()` all return DTOs directly (`File`/`Tracker`/`WebSeed`/`Peer`/`Piece`) via `requestDto()`/`toDto()` — the latter two still need their manual envelope-unwrap (`sync/torrentPeers`'s `{peers:...}` wrapper, `pieceStates`'s flat-list-to-`{index,state}` zip) since that shape isn't expressible as a plain `requestDto()` call, but the final values are hydrated too. `Base::relation()` (backs `Torrent`'s lazy `->files`/`->trackers`/`->peers`/`->pieces`/`->webseeds`) tolerates either raw arrays or already-hydrated DTOs from its backing `Client` method (`$v instanceof $class ? $v : new $class(...)`) — needed once these methods started returning DTOs themselves, since re-wrapping an already-hydrated DTO in `new Foo($dto, ...)` would throw (`Base::__construct()` expects an array).

### Per-DTO shape gotchas

- `Torrent` vs `Torrent/Properties`: different field sets from different endpoints (`/torrents/info` vs `/torrents/properties`), not one a subset of the other (e.g. `Properties` has both `is_private`+`private`, `dl_speed_avg`/`up_speed_avg`, `seeds_total`/`peers_total`) — kept as separate DTOs rather than merged. `Torrent::$inactive_seeding_time_limit` and `$max_inactive_seeding_time` are both real, distinct API keys (mirrors `seeding_time_limit`/`max_seeding_time`) — don't collapse them. `Torrent` has no `share_limits_mode` field (API never populates it) — don't redeclare the removed `ShareLimitsMode` enum for it.
- `Torrent::$hash`-keyed relation/mutator methods (`addTags`/`removeTags`, priority reorder, share limits, save/download path, tags/comment/webseeds/trackers) update local DTO fields in place — no refetch — so callers see the change immediately. `pause`/`resume`/`stop`/`start` are deliberately NOT wired into `Torrent`: updating `state` locally would require guessing the resulting `TorrentState` enum value, left to refetch instead. `renameTorrent` (not `rename`) avoids colliding with PHP's builtin-sounding name and disambiguates from file/folder rename.
- `Category`: `savePath` (legacy camelCase, always a string) vs `download_path` (snake_case, nullable — null for the built-in `RSS` category). `editCategory()` only accepts `category`+`savePath`(+`downloadPath`) — the other `Category` fields (`ratio_limit` etc.) aren't editable via this endpoint.
- `Preferences`: flat but huge (223 fields on this qBittorrent version) — property list was generated from a live response rather than hand-typed. `max_ratio` needed a manual `float` override (serializes as an int at its default value, but the real field is fractional). `setPreferences()` stays untyped — it PATCHes a partial array (only keys present in the payload are applied), not a full-object push, so it deliberately has no `save()`.
- `Rss/Rule` includes modern fields the docs omit: `priority`, `torrentContentLayout`, `torrentParams` (raw array). Its deprecated `addPaused`/`torrentContentLayout`/`savePath`/`assignedCategory` fields are **write-dead**: `AutoDownloadRule::fromJsonObject()` (server-side handler for `setRule`/`addRule`) uses `torrentParams` exclusively whenever the posted JSON contains that key at all — which ours always does. Each of the four is a `set`-hooked property that mirrors into the matching `torrentParams` key (`category`/`save_path`/`content_layout`/`stopped`, per `addtorrentparams.cpp`'s `PARAM_*` constants) on every write, so any assignment — including dynamic `$rule->{$key} = $val` — takes effect for real.
- `Rss/Feed`/`Rss/Rule` have a synthesized `$path`/`$name` field that **isn't a real API field** — the API only exposes a feed's path or a rule's name as the object's *key* in the parent response, never as a value inside it, so `Client::hydrateRssItems()`/`hydrateRssRules()` inject it during hydration. `Rss/Feed` has no real API `name`/`unread` fields — `/rss/items` returns a nested tree keyed by feed/folder name; a node with a `uid` key becomes a `Feed`, anything else is a plain nested-array folder (no `Folder` DTO). Per-feed fields (`title`, `lastBuildDate`, `isLoading`, `hasError`, `articles`) only appear with `withData=true`; `refreshInterval` only appears when > 0. `Client::setRssFeedUrl()`/`setRssFeedRefreshInterval()` are genuine granular per-field endpoints (unlike `Rule`, no whole-object `Feed` update exists) — wired as `Feed::setUrl()`/`setRefreshInterval()`, not the `Rule::save()` pattern.
- `/torrents/pieceStates` returns a flat `[state, state, ...]` array — `Client::getTorrentPiecesStates` zips it into `{index, state}` rows. Peer data comes from `/api/v2/sync/torrentPeers` (NOT `/api/v2/torrents/peers`, which 404s), a `{full_update, peers, rid, show_flags}` envelope unwrapped to `['peers']`. `Torrent/Peer`'s fields haven't been diffed against a live response with active peers (none connected on this box at audit time) — re-verify if a torrent ever has peers.
- `getTags()`/`createTags()`/`deleteTags()`/`addTorrentTags()`/`removeTorrentTags()`/`getTorrentPieceHashes()` — plain string arrays, no DTO needed.
- `Torrent/File::$url_path`/`$basename`/`$dirname`/`$size_human`/`$is_complete`/`$progress_percent` and `Torrent::$downloadable_files`/`$progress_percent`/`$is_complete`/`$size_human` are hooked `get` computed properties, not raw API fields. `$url_path` is deliberately relative/host-less (segment-wise `rawurlencode()` of `$name`, preserves `/`) — the DTO has no config access, so callers prefix the configured download host themselves.
- `Client::getSearchResults()` can't use `requestDto()` — the raw response `{results: [...], status, total}` would misfire `Base::toDto()`'s list-detection (treats any top-level array whose first key holds an array value as "list of DTOs"). Same problem class as `hydrateRssItems()`; solved with a matching private `hydrateSearchResults()`.
- Search group: the 5.0 wiki's documented field/shape names for `search/plugins` and `search/results` are wrong (paraphrased, not real) — confirmed against `src/webui/api/searchcontroller.cpp`. Real shapes: `search/plugins` returns a JSON **array** (not an object keyed by plugin name) of `{name, fullName, url, version, enabled, supportedCategories}`; each search result is `{fileName, fileUrl, fileSize, nbSeeders, nbLeechers, engineName, siteUrl, descrLink, pubDate}` (not `seeders`/`leechers`/`engine`); `search/status` returns an array of `{id, status, total}` even when queried with a specific `id`.
- `Search\Status::stop()`/`delete()`/`results()` wrap `stopSearch()`/`deleteSearch()`/`getSearchResults()`. `Search\Plugin::enable()`/`uninstall()` wrap `enableSearchPlugin()`/`uninstallSearchPlugin()`. Gotcha: after `deleteSearch($id)`, the server 404s on any further `search/status?id=$id` call (the id stops existing) rather than returning empty — don't call `getSearchStatus()` on a `Status` after `delete()`. `Search\Result` has no wrapper methods — no per-result endpoint exists.
- `Log/Message` (`getLog()`, `/log/main`) and `Log/Peer` (`getPeerLog()`, `/log/peers`) are flat, no action methods (log entries aren't mutable). `Message::$type` is a `LogMessageType` backed int enum (`NORMAL`=1, `INFO`=2, `WARNING`=4, `CRITICAL`=8 — a bitmask on the wire, but each entry only ever carries one bit in practice). `getLog()` defaults to `last_known_id=-1` (returns everything, capped at 20000 entries on this instance) — pass `['last_known_id' => $id]` to page forward instead of refetching the whole log.
- `Transfer` (`getTransferInfo()`, `/transfer/info`): flat, 10 scalar fields, incl. `last_external_address_v4`/`v6` (undocumented on the wiki). `getVersion()`/`getWebApiVersion()`/`transfer/speedLimitsMode`/`downloadLimit`/`uploadLimit` are plain-text (not JSON) responses — use `requestRaw()`, not `request()`. `setGlobalDownloadLimit()`/`setGlobalUploadLimit()` are named with a `Global` prefix to avoid colliding with the per-torrent `Client::{get,set}{Download,Upload}Limit()`. Gotcha: qBittorrent rounds a submitted byte limit to the nearest KiB server-side (999999 in → 999424 read back) — `Transfer::setDownloadLimit()`/`setUploadLimit()` still set the local field to the exact value passed, so it can drift from the server by up to ~1023 bytes until a refetch.
- `Qbittorrent\Helper::extractKey()` unwraps `JsonSerializable` values (all `Base` DTOs) before checking `is_array()` — needed once `Client` methods started returning DTO objects instead of raw arrays, otherwise it silently finds nothing.

## Git

- Repo is git with a private GitHub origin (`UnkyBadTouch/qbittorrent`).
- Consumed by `UnkyBadTouch/qbittorrent-tools` as a composer VCS dependency (`blackout/qbbittorrent`) — a breaking change here (namespace/signature) needs a bump + coordinated update on that side.
- Coding style is tabs, not spaces, Allman braces. `phpcs.xml` lives in the `qbittorrent-tools` repo (shared house style, not duplicated here).
